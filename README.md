# PK 撮合数据可视化

纯前端单页：按日期读取每日 `match_dump` 索引，渲染成「一对对」主播匹配卡片 + 准入漏斗。零依赖、零构建；本地文件拖拽仍作为兜底。

## 用法

打开页面根地址时，默认通过同源 `/boss/pk-match-kb/pk-kb/match_dump/{当天 yyyyMMdd}/index.json` 代理 BOSS 并打开最新一轮。顶部可直接选择其他日期，页面只替换日期目录；轮次仍按小时分组。

`serve.sh` 将 `/boss/*` 固定代理到 `https://boss.hdslb.com/*`，每日索引及其中的 dump 地址都会转换为同源代理地址，避免浏览器 CORS；代理目标固定，不接受任意外部 URL。

### 网络暴露约定

`serve.sh` 默认绑定 `0.0.0.0`，这是本项目用于局域网分享可视化页面的预期行为；启动后，同一局域网内的设备可通过本机内网 IP 访问页面、`dumps/` 文件及固定的 BOSS 代理路由。除非明确要求仅本机访问，否则不要在运行时擅自改成 `127.0.0.1`，也不要因为安全顾虑删除或替换原始启动脚本。需要私密调试时，应由操作者明确选择仅回环绑定。

企微通报仍可通过 `?index=<当天每日索引实际地址>` 精确打开 BOSS 索引；未带参数时使用上述同源每日路径约定。

直接双击 `index.html` 时仍可点「选择文件」或把 `.json` 拖进页面，适合索引/BOSS 不可用时本地排查。

本仓库不附带 dump 数据；需要本地排查时，可通过「选择文件」或拖拽你自己的 `.json` 文件导入。

选择成功后，文件名会以 `?dump=文件名` 写入当前 URL，解析后的 dump 同时保存在浏览器 IndexedDB 中。刷新页面时会按 URL 自动恢复；数据只保存在本机浏览器，不会上传。若浏览器缓存被清理，需要重新选择原文件。

旧的 `?dump=文件名` 分享链接仍会读取同源 `dumps/文件名`；这是兼容兜底，新链接统一使用远端索引。

## 数据来源

文件是 `income-play-job` 的 `pk_low_pcu_random` 撮合服务每轮上传 BOSS 的匹配快照：

- BOSS dump key：生产 `{keyPrefix}/match_dump/{yyyyMMdd}/{执行时间}_{模型名}.json`；UAT `uat-{keyPrefix}/match_dump/{yyyyMMdd}/{执行时间}_{模型名}.json`
- 每个 dump 上传成功后，覆盖 `{keyPrefix}/match_dump/{yyyyMMdd}/index.json`。每日索引只包含当天 JSON 的 `name/stamp/hour/key/url/size`，按最新轮次在前排列。
- 私有桶默认在索引和企微链接中使用 7 天有效的预签名 GET 地址；配置 `Boss.PublicBaseURL` 时改用稳定公开地址。两种方式都要求 BOSS 允许页面来源跨域 GET。

数据契约见 income-play-job 的 `internal/service/pk_low_pcu_random/dump.go`（`matchDump`）。

## 展示内容

- **顶部**：时间、环境、DRY-RUN/LIVE、成交对数。
- **自动总结**：把分池覆盖、LLM 成功、AI 贡献和画像可用性压缩成三句话，并按分池冲突、调用失败、画像不可用、覆盖不足、兜底偏高的优先级给出一条处理建议；完全在浏览器本地按规则计算，不再次调用 LLM。
- **按需下钻**：运行诊断、漏斗、质量和版本对比默认收起；逐对卡片单独收起，需要排查时再展开。
- **画像缺失**：单轮显示画像表无记录人数及画像过期人数；多轮汇总显示人次。
- **漏斗**：在播 → PCU → 开播时长 → 冷却 → 拒绝 → 营收 → 接受PK开关；页面忽略后置 `after_canstart/admitted`，匹配覆盖统一以 isolated/AI/random 三池人数之和为分母。
- **双方确认结果**：发邀请后 job 会回扫 `new_pk_rec_record` 约 1 分钟，把双方点没点补进 dump。面板展示「发出邀请 → 流水落库 → 双方都接受 → 成功建 PK」观测漏斗，以及仅一方响应/双方未响应/被拒绝/窗口内未定/未落库的分解。
  - **接受率分母是「已落库的对」（`found`）**，不含没落库的对——邀请可能被 pk 侧前置校验拦在写库之前，把它算进分母会低估接受率。
  - **`窗口内未定` 不等于「没配上」**：确认卡超时是端上调 `MatchRecHandle` 上报的，可能发生在观测窗口之后，这些对的最终结局本页看不到。要看最终成交率需要另外回扫历史流水。
  - `双方都接受` 取 `ext` 双确认位；`成功建 PK` 额外要求 `new_pk_id` 回填（双接受后建 PK 仍可能失败）。
  - 扫表取满行数上限（`scan_capped`）或观测降级（`degraded`）时面板会显式告警，此时「未落库」数不能直接采信。
  - 没有任何一轮做过观测（旧 dump、全 dry-run）时整个面板隐藏，不会把「未观测」显示成「0 对接受」。
- **LLM 诊断**：模型与配置快照、调用成功率、重试、耗时、Prompt 大小，以及返回 → 合法 → 接受的配对漏斗和逐轮明细。
- **链路追踪**：新版 dump 的每个 AI 对可展开查看池 → 轮次/分组 → LLM 调用 → 组内校验 → 判重/黑名单 → 发送决策；fallback 对展示随机兜底路径。
- **版本对比**：同时导入两份以上 dump，按模型、Prompt 指纹、Rules、KB 和 schema 组合聚合，对比覆盖、LLM 接受率、AI/同区占比、PCU/营收差距与发送率。
- **深度分析**：营收档矩阵、档位可信度、重复曝光、重复房间对、灰度与 dump 健康检查。
- **卡片**：每对一张，优先展示房间关键帧/封面、主播头像昵称、房间标题、大小分区和直播间入口；左右主播可展开量化画像，对比营收标量、胜率/逃跑率/完赛率、PCU、粉丝、舰长、风格与偏好，并展示完整配对链路。
- **筛选**：可按昵称、uid、房间、标题、分区或 reason 搜索，按来源、同区/跨区、发送状态过滤；有观测数据时额外出现「确认结果」筛选（双方接受/已建 PK/窗口内未定/被拒绝/未落库）与「双方接受优先」排序。当前结果 CSV 同样包含房间展示字段与 `confirm_*` 列（未观测的对留空，不写 0/false）。
- **多轮**：一次选择多份 dump，可查看趋势、重复主播与 24h 内重复房间对。

页面只接受当前 dump 契约。缺少 `runtime`、`knowledge`、`llm`、Prompt 指纹或 `pairs[].trace` 的旧文件会直接报错，不做兼容或降级展示。

`confirm_stats` 与 `pairs[].confirm` 是例外：旧 dump 缺这两项不报错，按「未观测」处理（`confirm_stats.watched` 补 `-1` 作哨兵），确认面板与相关筛选整体隐藏。存在时会校验字段形状。
